#### 🤖 Claude · 2026-10-19 01:38


The preview has to tell "nothing before the range" apart from "the day before was never processed". Only the Ledger knows which one applies.

**Why it's needed**
- The frozen contract's `PredecessorState` includes `ZERO_STATE`. A chain is in its zero state on A−1 when nothing affects it on or before A−1 (OQ-22, OQ-26 item 3):
  - **Positions:** no active trade dated on or before A−1.
  - **Cash:** no active entry of either type (trade or deposit/withdrawal).
- That changes what the user sees for cash. If A−1 has no `date_status` row:
  - with no entries before A, it's a valid start (`ZERO_STATE`);
  - with entries before A, it's `NOT_PROCESSED`, and the preview has to warn that the run will end `FAILED` with `CASH_PREDECESSOR_MISSING`.
- `date_status` alone can't tell these two apart. Both look like "no row".

**Why it's a separate interface instead of reading the ledger directly**
- Processing can't touch `ledger.entries`; cross-module reads must go through `ledger/public.py`. The only reads there are `LedgerReader.get_trades(start, end)` and `get_cash_movements(start, end)`.
- `ChainHistory` is a one-method interface (`has_entries_on_or_before(chain, day)`), so the service asks the question the spec asks, not "fetch every trade".
  - `LedgerChainHistory` answers it by calling `get_trades(date.min, A−1)`, and `get_cash_movements` too for cash.
  - Unit tests use a two-field fake instead of building ledger records.
- The Wave 4 worker needs the same rule on every date: the predecessor rule, and the OQ-22 refusal when the run starts. So it gets reused.

**The weak spot:** with no "is there any entry?" read on `LedgerReader`, the adapter loads every trade up to A−1 just to check for one. It's only one call per chain per preview, but it's wasteful. I left a contract request for lane X in the shared notes to add a cheap existence read to `LedgerReader`. If that lands, only the adapter changes.

**If you'd rather keep it simpler**, two options:
1. **Drop the interface** and call `LedgerReader` directly in `ProcessingService`. One less file, but the service then depends on the ledger's read shape and the tests need ledger records.
2. **Keep the interface and rename it**, for example `ZeroStateReader`, if "chain history" reads as more than it is.
