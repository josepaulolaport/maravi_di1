**How it works:**
- **Pricing:** it now has one validator for a quote typed as a PU or a rate, with one set of pt-BR messages. It is exposed through `pricing/public.py` with a way to report errors on the caller's own field names. The calculator runs the same validator.
- **Ledger and Prices:** they keep only their own rules (Ledger: contract, quantity, input kind, cash fields, time, not after today; Prices: not after today). Their domain code can't import another module, so the validator is passed in as an argument and their services supply it.
- **`_as_request_error`:** kept, in a smaller form. Pricing can still refuse after validation (overflow, a PU that rounds to zero, unknown contract), and those errors use Pricing's field names. Removing it would mean changing the documented `PricingService.calculate` contract (OQ-34). It now reuses the same field mapping instead of its own copy.

**Messages that changed.** No error code or field changed, and the docs fix no message text:
- **Prices:** a PU ≤ 0 now says "O PU deve ser maior que zero." instead of "O valor deve ser maior que zero.".
- **Ledger, both values typed:** now "Informe apenas o PU, sem a taxa." or "Informe apenas a taxa, sem o PU.", instead of "Informe apenas o PU ou a taxa, não os dois.".
- **Ledger, maturity date:** a rate trade gets only "Na data de vencimento informe o PU.", even if the rate is missing or invalid. A date after maturity is now reported together with the other input errors, not after them. This is what Prices already did.
- **Calculator:** its messages now match the ones the screens already showed ("−100%" instead of "-1", "Use no máximo N casas decimais.", "Informe um número válido.", "O contrato já venceu nesta data.").
