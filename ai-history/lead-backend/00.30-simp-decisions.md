Decisions to record:
- **A2:** AUM is no longer stored; it is computed at read time as cash + Σ market value, only when both chains are processed on that date (null otherwise). Amends OQ-21/OQ-38.
- **A3 / option 1:** RabbitMQ carries one message per processing request (its request_id), published through the outbox in creation order. The worker consumes one at a time; on a message it locks that request and runs it only if it is still QUEUED (otherwise acks and skips). A periodic sweep in the worker (every few seconds) runs any QUEUED request left without a message, oldest first, so a lost message only delays a run. PostgreSQL keeps status and history. Removed: inbox and its retention, dead-letter queues, delivery limit, redelivery backoff, the after-ack job queue. Replaces OQ-46's doorbell; keeps "one worker, one run at a time".
- **A10(b):** Carteira marks a position row whose current reference price was registered after the date was processed ("Preço alterado após o processamento — reprocesse"), comparing the price's created_at (prices are re-registered with a new id per OQ-25) with the date's portfolio_processed_at. OQ-30/31 otherwise unchanged.
- **A1:** "Processando" is no longer stored per date. Each date goes from its old status to its new one in one transaction, and the read side shows Processando for the active run's current date (progress_date + 1). The *_previous columns become unused. Amends OQ-23/OQ-26.
