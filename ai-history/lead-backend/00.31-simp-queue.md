Target design:
1. POST /processing/requests saves the request QUEUED and, in the same transaction, one outbox message `processing.run` carrying `{"request_id": ...}`. The relay publishes in outbox order.
2. The single worker consumes with prefetch 1. On a message it locks that request; if it is QUEUED (and no run is RUNNING) it sets it RUNNING and runs it; if not (cancelled, done, or already taken by the sweep) it acks and skips. Ack policy: ack when the run's start commits (as today); recovery at startup handles crashes.
3. A periodic sweep in the worker (every few seconds, configurable) runs the oldest QUEUED request when no run is RUNNING, so a lost or dead message only delays a run. At startup: recovery first, then one sweep.
4. Keep "one run at a time" atomic: there will be an advisory lock in take_next from the parallel correctness PR (branch claude/simp-correctness-…, session simp-correctness); reuse it when you merge it in.

- A message arriving during a run is acked at once and skipped, and the sweep after the run picks up its request. A bad message is logged and acked.
